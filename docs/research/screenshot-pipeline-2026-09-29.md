## Ledger

| # | Source (version / date) | Observed issue or useful pattern | Applicability to Varve | Design decision | Regression test |
|---|---|---|---|---|---|
| R1 | Playwright docs, *Visual comparisons* (accessed 2026-09-29, Playwright 1.62.1) — https://playwright.dev/docs/test-snapshots | Docs state plainly: "Browser rendering can vary based on the host OS, version, settings, hardware, power source (battery vs. power adapter), headless mode"; snapshots are named per browser+platform; `toHaveScreenshot` needs two consecutive matching captures. | Varve's marketing captures are *not* comparison baselines, but the website *does* keep `visual.spec.ts` baselines. The two must not be conflated. | Keep marketing publication approval separate from `toHaveScreenshot` baselines; record capture environment (viewport/DPR/browser) in the manifest instead of assuming pixel identity across hosts. | `apps/website/src/test/screenshots.test.ts` asserts recorded dimensions/provenance; visual baselines stay in `visual.spec.ts-snapshots` and are never written by the capture script. |
| R2 | Playwright issue #42962, opened **2026-09-28**, status **Open**, no labels — https://github.com/microsoft/playwright/issues/42962 (firsthand reporter) | On Chromium **headless shell**, `Page.captureScreenshot` with `captureBeyondViewport: true` re-applies WebPreferences and *drops Playwright's default font families*, changing layout of anything below the viewport. Reporter reproduces on macOS and in Linux Docker (monospace only). Root cause is in `page_handler.cc`/`web_view_impl.cc`; #42617 re-sends touch emulation but not fonts. | Varve captures at a fixed 1440x900 viewport and never uses `fullPage` for product scenes, so the trigger (`captureBeyondViewport`) is not exercised by `product.mjs`. The website's `visual.spec.ts` **does** use `fullPage` and stitches long pages — but it pins `@fontsource-variable` families by name, so a generic-family substitution would not silently change the intended face there. | Do not adopt `fullPage` for product captures; keep fixed-viewport captures. Treat this as a reason to make font readiness explicit in `product.mjs` rather than trusting an implicit default. | New `waitForFonts` + `requireFonts` readiness in `product.mjs`; `settle()` fails loudly when the expected family is not loaded. |
| R3 | Playwright issue #19861, opened 2023-01-04, status **Open**, label `P3-collecting-feedback` — https://github.com/microsoft/playwright/issues/19861 | Lazy-loaded content missing from full-page captures is an open, unresolved limitation; the issue collects workarounds (scroll to bottom, `scrollIntoViewIfNeeded`) rather than endorsing one. Scrolling to trigger lazy loads mutates scroll state. | Directly relevant to *website* validation, not to product capture: the Varve homepage/feature pages lazy-load screenshots and the visual specs already warm-scroll + wait for `img.complete && naturalWidth > 0`. | Keep the existing warm-scroll + decode wait for website validation; add an explicit decoded-source check for the image under test rather than a blanket scroll workaround. Do not enlarge the viewport to fake a full-page capture. | Website delivery spec added by this task waits for `currentSrc` + `naturalWidth` at each breakpoint. |
| R4 | Chromatic, *Unstable tests* (accessed 2026-09-29) — https://www.chromatic.com/docs/unstable-tests/ | Enumerates causes of unstable captures: missing resources, responsive-source/cache instability, clipped content, and video-capture tradeoffs. Chromatic processes snapshots remotely, so its output is not an unmodified application screenshot. | Confirms the failure classes to guard: responsive-source selection instability and clip/fit mistakes. Reinforces that a hosted snapshot service is not an acceptable substitute for a real capture. | Derive responsive `srcset`/`sizes` from the actual component layout and verify `currentSrc`; fix the `object-fit: cover` clip defect; keep captures local and unprocessed as the authoritative artifact. | `apps/website` delivery spec asserting `currentSrc`, intrinsic dimensions, and full-image visibility; pipeline image analysis rejecting clipped/blank output. |
| R5 | Playwright *Page* API / readiness guidance (accessed 2026-09-29) | `networkidle` is not a readiness signal for a rendering app; auto-waiting asserts on locators/element state. | `product.mjs` used a fixed `waitForTimeout(1500)` after opening a document and never asserted *which* document loaded — a false-success path. | Replace the sleep with a real identity assertion on the editor's own document heading and a bounded canvas-stability wait. | `product.mjs` readiness helpers + the capture self-check in the audit doc. |
| R6 | Astro docs, *Images* (accessed 2026-09-29, Astro 7.2.1) — https://docs.astro.build/en/guides/images/ | "Files in the `public/` directory are always served or copied into the build folder as-is, with no processing." Responsive images are not supported for `public/`. `<Image>`/`<Picture>` need the default Sharp service; "When using a strict package manager like pnpm, you may need to manually install Sharp." A documented `passthroughImageService()` exists for environments without Sharp. | Varve serves every screenshot from `public/screenshots/`, so no optimization happens at all, and `sharp` is absent — `<Image>`/`<Picture>` would fail today. Moving to `src/assets` would break the stable `/screenshots/<file>` references used by `docs/` and `README.md`. | Keep `public/` and the stable `/screenshots/*` paths; generate explicit, reviewed derivatives in the pipeline and emit `<picture>`/`srcset` from the manifest. Do not add a dependency the repo does not otherwise need. | Manifest variant metadata validated for existence, byte equality and dimensions; website spec asserting only declared variants are referenced. |
| R7 | web.dev, *Fetch priority* (accessed 2026-09-29) — https://web.dev/articles/fetch-priority | Above-the-fold LCP imagery should not be lazy-loaded and benefits from an explicit high priority hint. | `ProductShowcase` marks the primary screenshot `loading="eager"` but sets no `fetchpriority`, and the missing-image placeholder leaks a developer command to visitors. | Set `fetchpriority="high"` on the primary above-fold image; keep detail crops `lazy`; move developer diagnostics out of visitor-facing fallbacks. | Website spec asserting priority attributes and visitor-safe fallback copy. |
| R8 | W3C WAI, *Complex images* (accessed 2026-09-29) — https://www.w3.org/WAI/tutorials/images/complex/ | Informative images that carry complex information need a short `alt` plus an extended description in text; alt text is not a place to dump UI transcription. | Varve screenshots carry real information (panel names, control states) that a short alt cannot fully convey; the surrounding caption already carries some of it. | Keep concise `alt`, keep the caption as real page text, and add an accessible enlargement for detail crops so the UI text is readable without stuffing alt. | Accessibility spec: labelled trigger, Escape/focus return, and real page text adjacent to the image. |
| F1 | r/AppStoreOptimization redesign review, 2026-08-08 (firsthand reviewer) | "Some of the supporting text is so tiny it will be unreadable at App Store size"; advice is "bigger product UI", remove tiny copy. | Same class of failure as a scaled-down full editor frame shown at a third of the page width. | Keep crop-at-capture for detail scenes; make the crop policy state intent rather than force every crop into one 4:3 `cover` window. | Visual inspection of the built showcase at 390/768/1280/1440 + the crop/fit regression spec. |
| F2 | pageloop / vidocu / screenhance / r/SaaS threads (2025-04 → 2026-09) | Consistent firsthand framing: screenshots are the part of a product site that goes stale silently, they cannot be grepped, and a stale screenshot "looks completely fine" until a customer notices the button moved; "wrong" images showing removed features are worse than merely stale ones. | Varve's manifest-driven pipeline already deletes a skipped scene's old file, but nothing tied a capture to the revision it was validated against, and `lastValidatedAgainst` was written as permanent `null`. | Record real source identity (`sourceRevision`, `sourceDirty`, `sourceDigest`) at capture time and populate `lastValidatedAgainst`; validate that a captured file's provenance is not fabricated. | `validate.mjs` + `screenshots.test.ts` assert provenance shape; the audit doc records the previous state. |
| F3 | Launch Shots, *11 common App Store screenshot mistakes*, 2026-04-25 (firsthand review of thousands of listings) | "The app UI should occupy at least half the screenshot"; hiding the UI is a red flag; unreadable-at-thumbnail-size is the top failure. | Argues against any crop policy that clips the panel a caption names, and against decorative chrome swallowing the canvas. | Detail crops must show their whole subject (`contain`, intrinsic aspect); website chrome stays outside the captured pixels. | Crop/fit regression spec + visual inspection of each detail image at display size. |
| F4 | screenhance, *7 screenshot mistakes*, 2026-04-21 (firsthand checklist) | Names two Varve-relevant failure modes: mockups "featuring features that quietly got removed", and engineering-led sites showing "raw screenshots straight from the browser" with inconsistent framing. | Varve's `SCENES` registry is the guard against removed features (pruned scenes delete files), but nothing prevented a *hand-copied* asset bypassing the manifest, which is exactly what `performance-settings-dark.png` was. | Route every website screenshot through the manifest; make the validator fail on any PNG in the published or canonical directory that no manifest entry owns (with a documented, narrow registry for E2E-produced source assets). | `validate.mjs` source-asset registry + orphan check; reproduced failure recorded in the audit doc. |

## Deliberate boundaries

- **No competitor feature survey** beyond the failure patterns above; the
  entries were kept because each changed a decision.
- **No hosting/infrastructure migration.** The existing review-directory and
  checksum-checked sync workflow is extended, not replaced.
- **No AI-generated product imagery.** Every capture is the real editor; the
  only non-captured composition is the existing OG social card, which is
  explicitly outside the raw capture.
- **Native parity is not claimed.** All evidence here is a Chromium/headless
  browser runtime; desktop-native (Tauri) behaviour is out of scope for these
  captures and is not asserted by them.
