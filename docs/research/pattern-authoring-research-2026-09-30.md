# Pattern authoring research (2026-09-30)

This note records focused product and renderer evidence used to guide Varve's
pattern-authoring work. Issue reports are individual, version-specific reports;
they do not establish how common a problem is or prove the same defect exists
in Varve.

| Source and version | Finding | Varve decision | Acceptance check |
|---|---|---|---|
| [Adobe Illustrator: Create and apply patterns](https://helpx.adobe.com/illustrator/using/create-edit-patterns.html), help updated 2026-08-31 | Selected artwork can become a pattern through a dedicated make/edit flow; new patterns enter Swatches and editing an existing swatch updates its definition. | Keep source editing distinct from a fill instance. Preserve the selected artwork, expose definition scope and usage, and put reusable definitions in the existing library surface. | Create from selection leaves originals intact; edit one shared definition and confirm every linked use changes; Make Unique isolates one use. |
| [Adobe Photoshop: Create a new pattern](https://helpx.adobe.com/photoshop/using/pattern-preview.html), help updated 2026-02-23 | Pattern Preview repeats artwork outside the canvas, with the documentation recommending Smart Objects for the workflow. | Show neighboring cells while editing, but keep preview copies as view state rather than scene objects. | Edge and corner edits update neighboring previews without increasing source-node count or creating extra history entries. |
| [Inkscape report #5971](https://gitlab.com/inkscape/inbox/-/issues/5971), reported against Inkscape 1.1.1 (2021) | A user reports pattern transform handles can be far from the filled object, dragging is hard to reproduce, and transparent pattern color is awkward. | Keep transform handles near the edited fill and offer numeric controls and transparent backgrounds. | Keyboard and numeric transform edits work in a compact inspector; handles remain visible after zoom and selection changes. |
| [Inkscape report #1018](https://gitlab.com/inkscape/inkscape/-/issues/1018), Inkscape 1.1 development build (2020); closed with merged MR !4609 in July 2022 | Users and a maintainer traced zoom-triggered gigabytes of allocation and black/vanishing output to a tile surface sized to the zoomed object rather than visible/useful content; a user confirmed it, and the issue links later fixes. | Bound surface bytes and repetition work by visible bounds and effect influence; do not allocate an entire destination-sized pattern field for a swatch or preview. | Dense-repeat and zoom tests stay within configured surface and instance budgets and return an explicit preview/export limitation instead of partial output. |
| [Inkscape report #3807](https://gitlab.com/inkscape/inbox/-/issues/3807), Inkscape 1.0.1 (2020) | A user reports a pattern visible in the document intermittently disappearing in selected-area PNG export. The fetched report does not show a resolution. | Treat export as a separate acceptance surface; resolve every source before encoding and never report a missing-resource fallback as successful artwork. | Export through the UI, decode output pixels, and verify non-background pattern pixels and required source dependencies. |
| [resvg report #882](https://github.com/linebender/resvg/issues/882), opened 2025-02-10 and still open on 2026-09-30 | The issue body reports a slight rightward shift in resvg at 2000px compared with librsvg and Chrome/Firefox/Safari; the reporter says Illustrator differs substantially too. The current public-thread fetch showed no replies, so the prompt's described zoom-threshold replies were not independently confirmed. | Preserve fractional authored geometry and validate SVG output at several output sizes and scales. Compare independent renderers; do not treat a successful browser preview as proof of export parity. | Render the same fractional pattern at adjacent output widths and multiple scales; verify phase stability against Varve's source geometry and document renderer-specific differences. |
| [resvg report #628](https://github.com/linebender/resvg/issues/628), opened 2023-05-21, currently open and labelled blocked | The maintainer report says the tiny-skia path accepts only integer tile offsets and links upstream subpixel-offset work. | Keep fractional repeat phase in the source model. The separate raster seam inspector intentionally exposes whole-pixel cyclic offsets only; where a renderer cannot preserve fractional phase, report the output limitation or use a tested fallback. | Fractional and negative repeat-phase tests plus decoded raster-offset output comparisons detect rounding drift and incorrect source rotation. |
| [Inkscape report #8521](https://gitlab.com/inkscape/inbox/-/issues/8521), Inkscape 1.3-alpha (May 2023); closed as duplicate and marked fixed by merged MR !5351 | The reporter describes the pattern rotation center jumping during a drag as the tile changes; a developer linked the duplicate, and the reporter later noted the merged fix. | Keep fill placement numeric and independently undoable; if drag handles are added, keep the transform anchor stable during the gesture and commit once on release. | Drag or numeric rotation preserves its declared center, and one gesture creates one history action. |
| [Inkscape report #11558](https://gitlab.com/inkscape/inbox/-/issues/11558), Inkscape 1.4 build from 2024, updated 2025-01-11 | A user reports PDF output with pattern fills at varied orientations/origins not matching the SVG view; the author suspects pattern origins were ignored. | Verify PDF independently and advertise only the currently supported axis-aligned grid subset; report unsupported transforms rather than silently changing their phase. | Render standard PDF and PDF/X pages and compare supported fills against source geometry; confirm unsupported cases produce a warning and no placeholder fill. |
| [Inkscape report #11557](https://gitlab.com/inkscape/inbox/-/issues/11557), Inkscape 1.4 build from 2024 | A user reports “pattern to objects” inserts the pattern source away from the target and deletes the patterned object; they expected clipped finite copies with identical appearance and editable parts. | Do not expose a misleading one-click Expand command. Any future expansion must preserve appearance, clip to finite bounds, estimate instance count, and be undoable. | Compare expanded output against the source fill within target bounds; enforce finite count/memory limits and one-step Undo. |
| [MDN SVG `<pattern>` reference](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Element/pattern), referencing SVG 2 | `patternUnits` defines the coordinate system for tile `x/y/width/height`; `patternContentUnits` defines content coordinates; `patternTransform` maps pattern coordinates to the target. `viewBox` changes the content relationship. | Serialize each coordinate relationship deliberately; do not substitute one attribute for another. Use safe, remapped IDs and resolve inherited `href` definitions on import. | Inspect emitted SVG and render it in at least two independent implementations; cover user-space and object-bounds cases, transforms, and inherited definitions. |

## Limits and scope

- These sources motivate concrete tests, not claims that every renderer or
  application has the same failure.
- Varve can import or replace a raster tile and show its repeated preview.
  Seam inspection can cyclically offset existing texels by whole pixels for
  tiles up to 16 MP; this changes phase and does not synthesize seam content.
  Wraparound brush behavior is not claimed.
- Grid, half-drop, brick, and mirror variants ship through the shared
  evaluator; a finite rectangular supertile is emitted only for the tested
  cases. Hexagonal and arbitrary staggered arrangements are not implemented.
