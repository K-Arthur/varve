## Executive Summary

Research focused on understanding how mature creative applications present themselves online, with particular attention to DaVinci Resolve's product storytelling depth and Figma's modern clarity. Key findings reveal distinct patterns in how professional tools communicate value, structure downloads, present learning ecosystems, and handle community/sustainability models.

## 1. DaVinci Resolve Research

### 1.1 Product Storytelling Approach

**Positioning Statement:**
- "Hollywood's #1 Post Solution" - immediately establishes professional credibility
- Emphasizes that "high end professionals working on feature films and television shows use DaVinci Resolve more than any other solution"
- Focuses on "incredible quality and creative tools that are light years beyond the competition"

**Narrative Structure:**
1. **Authority**: Hollywood/feature film usage establishes premium positioning
2. **Technical depth**: 32-bit float processing, patented YRGB color science, wide gamut HDR
3. **Comprehensive scope**: "All In One Solution for Post Production" with dedicated pages (Media, Photo, Cut, Edit, Fusion, Color, Fairlight, Deliver)
4. **Collaboration emphasis**: "Only solution that lets you grow and build your own multi user post production studio"
5. **Free tier positioning**: "The best creative tools shouldn't be limited to Hollywood" - free version for learning, Studio for professional work

**Key Messaging Patterns:**
- **Specific technical claims**: 32-bit float, YRGB color science, Emmy award-winning technology
- **Professional proof points**: Feature films, streaming television shows, Hollywood colorists
- **Page-based organization**: Each major capability gets its own "page" (Edit, Cut, Color, Fusion, Fairlight, Deliver)
- **Hardware ecosystem**: Extensive keyboard, panel, console offerings
- **AI-forward**: DaVinci 21 heavily features AI tools (IntelliSearch, CineFocus, Face Age Transformer, etc.)

### 1.2 Download Journey

**Download CTA Placement:**
- Clear "Download DaVinci Resolve Free!" section on main product page
- Two-tier model prominently displayed: DaVinci Resolve (free) vs DaVinci Resolve Studio (paid)
- Download page: https://www.blackmagicdesign.com/event/davinciresolvedownload

**Version Differentiation:**
- **Free version**: "Learn how to use the same tools that professional Hollywood artists use"
- **Studio version**: "Tons of additional effects, 3D and more"
- **Hardware upsell**: "Adding an editor keyboard, color control panel, or audio console lets you work even faster"

**Platform Communication:**
- Website doesn't prominently list specific OS requirements on main page
- Downloads page likely handles platform-specific packages
- Emphasis on professional hardware integration (panels, consoles)

### 1.3 Training & Learning Ecosystem

**Training Page Structure:** https://www.blackmagicdesign.com/products/davinciresolve/training

**Components:**
- **Certification program**: "Become a Certified DaVinci Resolve Professional!"
- **Training videos**: Organized by page (Edit, Color, Fairlight, Fusion)
- **Training books**: Physical learning materials
- **Training partner network**: "Find a DaVinci Resolve Training Partner" with search for online/classroom centers
- **Certified trainer program**: "Become a Blackmagic Design Certified Trainer"
- **Certified training partner program**: For institutions

**Key Insight:** DaVinci Resolve invests heavily in formal training infrastructure, treating education as a product pillar rather than an afterthought.

### 1.4 What's New / Release Communication

**What's New Page:** https://www.blackmagicdesign.com/products/davinciresolve/whatsnew

**Structure:**
- Version-specific sections (DaVinci Resolve 21)
- Feature categories: AI Tools, Photo, Cut and Edit, Color, Fusion, Fairlight, Next Generation Engineering, Tools for Content Creators
- Detailed feature descriptions with "Before/After" imagery for visual tools
- Specific technical details (e.g., "MultiMaster trim passes, layer list node graphs and group versions enhance color page workflow")

**Release Pattern:**
- Major version releases (21, 20, etc.)
- Feature categories aligned with page structure
- Heavy emphasis on AI capabilities in recent versions
- Technical depth in descriptions (not marketing fluff)

## 6. Funding & Sustainability Models

### 6.1 GitHub Sponsors

**Website:** https://github.com/open-source/sponsors

**Model:**
- Platform for direct financial support of open source projects
- **$40M+ given back to maintainers**
- 103 regions supported globally
- 4.2K+ organizations sponsoring

**For Maintainers:**
- Launch sponsor page in minutes
- Automatic worldwide recommendations to partners
- Showcase Sponsors buttons on profile/repositories
- Tax forms required for payments
- Bank and tax information required
- Two-factor authentication required

**For Sponsors:**
- Find and fund dependencies in single transaction
- Discovery and bulk sponsorship tools
- Flexible payment options
- Corporate invoicing (single invoice for all payments)
- Companies like Microsoft use it for consolidated billing

**Key Characteristics:**
- Integrated with GitHub ecosystem
- Tax compliance handled by platform
- Professional invoicing for corporations
- Global reach (103 regions)

### 6.2 Open Collective

**Website:** https://opencollective.com/

**Model:**
- "Raise, manage and disburse money with full transparency"
- Collaborative money management platform
- Stewarded by Open Finance Consortium (nonprofit 501(c)(6))

**Key Features:**
- **Fiscal Hosting**: Connects collectives with legal entities that provide legal status and hold money
- **Crowdfunding**: One-time contributions, monthly recurring goals, yearly memberships
- **Transparent finances**: Public ledger showing all financial activity
- **Expense management**: Submit, review, approve invoices and reimbursements
- **Tiers**: Flexible tier system for different contribution levels

**Pricing (2026 update):**
- **Hosted Collectives**: No platform fees, only host fees (typically 8% of donations, drops to 6% after $500k, 4% after $1M)
- **Organizations**: Usage-based pricing (Discover: $0/month, Basic: $60/month, Pro: $320/month)
- Shift from percentage-based to usage-based model

**OC Foundation (Fiscal Host):**
- Nonprofit status + fundraising + money management software
- Hosts 600+ groups, $13M+ annually
- 8% fee structure with volume discounts
- Legal and tax compliance handled
- No minimum balance, no monthly fees
- Crowdfunding tools, transparent finances, automated recurring donations

**Key Characteristics:**
- Focus on transparency (public ledgers)
- Fiscal hosting removes legal/admin burden
- Community-owned platform
- Flexible contribution models (one-time, recurring, tiers)
- Expense management and reimbursement workflows

## 8. Solo-Developer Sustainability Insights

### 8.1 Funding Mechanisms

**GitHub Sponsors:**
- Pros: Integrated with GitHub, professional invoicing, global reach, tax compliance
- Cons: Requires tax forms, bank info, 2FA; platform takes fee; tied to GitHub ecosystem
- Best for: Projects with GitHub presence, corporate sponsors, need for professional invoicing

**Open Collective:**
- Pros: Fiscal hosting removes legal burden, transparent finances, flexible contribution models, community-owned platform
- Cons: Host fees (8% typical), requires finding fiscal host, platform complexity
- Best for: Community projects, need for fiscal hosting, want transparency, diverse contribution types

**Direct Donations (PayPal, Stripe):**
- Pros: Simple, direct control, lower fees
- Cons: No fiscal hosting, legal/admin burden, no community features
- Best for: Simple tip jars, established legal entities

### 8.2 Solo-Developer Considerations

**Challenges:**
- Legal/tax compliance burden
- Administrative overhead
- Limited time for community management
- Need for sustainable, predictable income
- Balancing development with support/community

**Successful Patterns:**
- **Transparency**: Open books, regular updates (Krita monthly reports)
- **Community ownership**: "Owned by contributors" messaging
- **Focus on mission**: "Affordable tools for everyone" (Krita)
- **Low-friction support**: Clear issue reporting, documentation-first approach
- **Realistic expectations**: Solo-developer identity as strength, not weakness

### 8.3 AGPL Licensing Considerations

**Strata is AGPL-3.0-or-later:**
- This is a copyleft license, not permissive like MIT
- Requires derivative works to be under AGPL
- May affect commercial adoption
- Should be clearly communicated on website
- Different from "open source" in common understanding (which often implies MIT/BSD)

**Communication Strategy:**
- Be explicit about AGPL license
- Explain implications for users
- Distinguish from permissive open source
- Position as ethical choice, not limitation
- Consider dual-licensing if commercial adoption is goal

## 9. Key Takeaways for Strata Website Strategy

### 9.1 Positioning Lessons

**From DaVinci:**
- Use technical depth to establish credibility (IR-replay, 86fps, Rust engine)
- Organize features by capability "pages" or chapters (Canvas, Typography, Motion, Export, etc.)
- Emphasize what makes it unique (local-first, cross-platform, native performance)

**From Sketch:**
- Lean into solo-developer identity as differentiator ("made by a different kind of company")
- Be honest about independence from VC/corporate pressure
- Focus on designer/user needs, not enterprise features

**From Open Source:**
- Community ownership messaging ("owned by contributors")
- Freedom and autonomy themes
- Transparent development (regular updates, honest roadmap)

### 9.2 Download Experience Lessons

**Platform Clarity:**
- Explicitly list supported platforms: Linux x86_64, macOS Universal, Windows x86_64
- Be honest about what's NOT supported (ARM variants)
- Package format variety: AppImage, deb, rpm, dmg, msi, nsis, AUR
- System requirements based on actual dependencies (WebKitGTK, GTK3, etc.)

**Integrity & Trust:**
- Checksums for downloads (currently missing - should add)
- Clear version information
- Release notes with technical depth
- Honest about what's signed vs unsigned

### 9.3 Feature Communication Lessons

**Depth over Breadth:**
- Don't list 40 tiny feature cards
- Create capability chapters: Canvas & Rendering, Vector Tools, Typography, Color & Effects, Motion & Prototyping, Export & Code Generation
- Use technical depth where appropriate (IR-replay, 86fps, Rust engine)
- Distinguish between "built and functional" vs "types only" (from Product Truth Matrix)

**Honesty about Maturity:**
- Use "In Development" or "Coming Soon" for partial features
- Be explicit about what's types-only vs wired
- Roadmap section for transparency

### 9.4 Learning & Support Lessons

**Documentation-First:**
- Leverage existing docs (AGENTS.md, architecture docs, audit docs)
- Create getting started guides
- Keyboard shortcuts reference
- Troubleshooting guides

**Community Building:**
- Clear contribution guidelines
- Issue reporting templates
- Non-code contribution paths (testing, documentation, design)
- Honest support expectations for solo developer

### 9.5 Sustainability & Support Lessons

**Funding Strategy:**
- Consider GitHub Sponsors for integration with existing repo
- Consider Open Collective for fiscal hosting and transparency
- Be explicit about what support enables
- Avoid "donation" terminology if AGPL copyleft makes it more like licensing

**Support Architecture:**
- Tiered support: Documentation → FAQ → Troubleshooting → Issue reporting
- Clear bug report guidelines
- Honest response time expectations
- Community forum or GitHub Discussions for peer support
