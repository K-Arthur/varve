# ADR-0214: Multi-resolution tiled raster pyramid (display LOD)

- **Status:** Accepted
- **Date:** 2026-08-09

## Context

`paintRasterLayer` (replay.ts:1986-2074) always materializes a full-layer-sized
surface and composites it with one `drawImage`. The 2026-08-03 measurement
(`docs/perf/raster-tiling-decision.md`) shows the frame budget is blown at
2048² (58.67 ms p95 vs 16.7 ms) and the intermediate alone is 256 MiB at
8192² — larger than the whole 128 MiB worker bitmap budget. Work is
proportional to total source tiles, not visible pixels. Dirty-tile-only replay
(`RasterLayerCache`) is shipped; visible-tile/LOD rendering is not. A full
repository audit is recorded in
`docs/architecture/raster-pyramid-audit.md` (findings F1-F8).

## Decision

D1 — **The pyramid is a derived, disposable render acceleration structure.**
Scene tiles (128×128, `Map<"col:row", {pixels, version}>`, sparse) remain the
single authoritative editable source. Pyramid levels are memory-only, never
serialized into the document, never part of undo history. A missing or cleared
pyramid is always regenerable from source; document open never depends on it.

D2 — **Virtual sparse pyramid.** Levels L0..LN (L0 = 1:1, LN = 1/2^N), each
level tiled at 128 px, allocated on demand. Empty levels/tiles allocate
nothing. Derived tiles are keyed by a composite identity that includes
layerId + revision + level + col/row + resampler version + pixel mode —
never bare coordinates or node ids.

D3 — **Incremental invalidation.** A base-tile edit bumps its L0 version and
invalidates only affected ancestor tiles (≥1, ≤4 per level). Derived tiles are
regenerated lazily by demand and priority. Generation never runs
synchronously during pointer handling.

D4 — **Revision safety.** Every generation job carries the revision it was
issued for; a stale result (any ancestor/level source version changed while the
job ran) is discarded. Never rely on component-mount state alone.

D5 — **Adaptive renderer.** Two coexisting paths:
- retained whole-layer surface (`RasterLayerCache`) — unchanged fast path for
  small layers, high coverage, and every case where effects/masks/blends need
  whole-layer parity;
- spatial tiled LOD — for large layers at low zoom / low viewport coverage.
Selection uses a measured crossover heuristic (source bytes, visible-area
ratio, selected LOD, visible tile count, memory profile), exposed in
diagnostics. No regression is allowed for common-sized documents.

D6 — **LOD selection from effective device-space scale.** Scale =
camera zoom × DPR × node/world affine (translation, rotation, skew,
non-uniform scale). Select the level closest to one pyramid texel per device
pixel, with a hysteresis band to prevent zoom thrash. pixel-mode layers use
box/nearest LOD policy.

D7 — **Deterministic resampling.** Coarse levels are generated by
premultiplied-alpha-aware, deterministic downsampling from the nearest finer
level, with the option of regenerating from authoritative source where
quality requires it. Output is identical across main thread, worker, and any
future native provider (one semantic contract, parity-tested).

D8 — **Progressive refinement.** When the ideal level is not resident, display
the best available correct representation (coarser ancestor upscaled, else
bounded finer fallback, else existing render path) and refine asynchronously.
No transient blanks during zoom.

D9 — **Bounded scheduling.** Pyramid generation runs on the existing
`background` scheduler lane (respecting interaction settle), with bounded
concurrency, priority ordering (viewport → interaction → near-viewport →
prefetch → background), deduplication, cancellation, latest-wins revision
checking, and idle-time prefetch limited to adjacent tiles / one LOD during
pinch.

D10 — **Unified memory budgeting.** Pyramid residency is tracked separately
(source bytes, encoded bytes, decoded tiles, in-flight buffers) and routed
through the existing budget resolver and pressure profiles ('normal'/'4gb'/
'2gb'). Under pressure: shrink residency, disable prefetch, prefer coarser
LOD. LRU is augmented by a cost-aware eviction policy (visibility, distance,
regeneration cost) — start simple, evolve from traces. The tile actively being
presented is never evicted mid-use.

D11 — **Correctness over optimization.** Tiles drawn with 1-N px gutters /
edge duplication to eliminate seams. Effects, masks, and blend modes that
cannot be proven tile-safe with parity fall back to the retained whole-layer
surface. Blend parity is proven by pixel tests, not assumed (repeated
per-tile drawImage ≠ single finished-surface composite).

D12 — **Export/print never consume display LOD.** Export uses the authoritative
source at the target resolution; print/PDF use source quality. The pyramid is
an interactive-display acceleration structure only.

D13 — **Encrypted documents never leak derived pixels.** If a document is
encrypted, pyramid residency is session-only; no derived raster data is
written to any persistent cache.

D14 — **WebKitGTK stays first-class.** Feature-detect workers/OffscreenCanvas/
createImageBitmap; maintain a main-thread fallback; no Chromium assumptions.
Pyramid tile transport uses transferable buffers (ImageBitmap/ArrayBuffer),
never `number[]` arrays (finding F4).

D15 — **Platform/package ownership.** `@varve/scene` owns only the
authoritative source. `@varve/engine` owns the pyramid core, LOD selection,
and raster rendering (`rasterPyramid/` module). `@varve/editor` owns
viewport-driven scheduling, lifecycle, and diagnostics. No React concerns in
the engine; no renderer structures in the document schema. No new imports in
CanvasArea.tsx or Shell.tsx (hub-file ceilings); integration via thin
adapters.

D16 — **No persistence in this milestone.** Derived pyramid tiles are
memory-only; no disk cache, no schema bump, no document growth. Revisit with
measurements if generation cost justifies it (revision-addressed, bounded,
evictable, corruption-safe).

## Consequences

- Normal/small raster layers: unchanged fast path (D5).
- Large layers at low zoom: work proportional to visible tiles; resident bytes
  bounded by a pyramid budget instead of the full layer surface.
- New correctness surface (seams, alpha/colour resampling, transform parity)
  is covered by the corpus in the milestone plan; any parity failure falls
  back to the retained surface.
- `pixelMode` gains a real consumer (D6); `RasterLayerCache` budget gains a
  production wiring to memory presets.

## Rejected shortcuts

- Replacing the retained-surface path with a pyramid-only renderer (regresses
  common workloads).
- Serializing mip levels into the document JSON (bloats every save; breaks D1).
- Choosing LOD from raw editor zoom (wrong under rotation/DPR/transforms).
- Unbounded generation queues or `Promise.all` fan-out.
- Per-tile independent filtering where an effect is layer-global (breaks
  parity; D11).
