## Website and installed-release acceptance

Until the actual release is published and verified, the public download page
correctly continues to advertise `0.2.1`. Do not hand-edit the generated
website manifest or advertise draft assets. Publication must refresh the
verified release data, deploy the exact-source website/demo, and verify live
download links, hashes, version labels, mobile layout and feature availability.

Package acceptance requires the installed-production gates described in the
[candidate runbook](release-candidate-runbook.md): the published 0.2.1 file
seed, same-profile upgrade, save/reopen, editing/undo, and actual PNG/SVG/PDF
exports on the release platforms. Checksums, SBOM, provenance, attestation,
signing status and updater availability remain required on the uploaded bytes.

The [complaint-informed research](../research/design-tool-failure-modes-2026-10-02.md#release-acceptance-follow-up-2026-10-06)
connects file corruption, indefinite saving and AppImage installation failures
to these acceptance checks and truthful website guidance.
