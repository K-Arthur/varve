## Scope owned by this task

Stage 6 of the ChromeOS program — website experience, downloads, documentation,
and support truth. Specifically:

- Correct Chromebook/tablet access routing: a touch device is never told
  "there are no mobile or tablet builds" and is never pushed to a
  wrong-architecture desktop installer; ChromeOS is detected as its own route.
- Canonical user-facing documentation for the Chromebook routes (browser tab,
  installed web app/PWA, Linux ARM64 through ChromeOS Linux) and the
  constrained-device performance, input, file/offline/update/backup, and
  troubleshooting surfaces.
- Consistency checks that keep site claims aligned with the release manifest
  and the Stage 1–5 evidence ledger.
- Low-resource website performance and accessibility improvements on the
  marketing site (effects, motion, touch, hidden-tab behavior), measured
  separately from the editor.
- Documentation of what remains unpublished because no physical Chromebook run
  has happened.

The task does **not** claim Duet hardware validation. No Chromebook is attached
to this session; the Stage 1–5 device checklists remain the handoff.
